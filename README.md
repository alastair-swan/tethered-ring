# TetheredRing

A Tethered Ring is a dynamic structure that can cost-effectively support space launch facilities, transportation infrastructure, and a sizable human settlement at high altitudes. An altitude of 32 km and a population of 250,000 is shown to be achievable using circa 2017 science and technology. The structure resembles a pipeline formed into a ring having a diameter similar to that of Earth's moon. It stays aloft primarily by generating and properly combining inertial forces with tensile forces to offset the pull of gravity. The inertial forces are produced by the circular motion of magnetically levitated rings within the pipeline, and the tensile forces are generated by appropriately tethering the pipelines to the planet using stays made of strong, light-weight, industrial fiber. The entire structure can be fabricated on Earth and neither its construction nor its deployment depends on a pre-existing space infrastructure or space-based industry. The deployed structure is resilient to catastrophic failure because its precision-guided fast moving components are: a) not exposed to seismic or climatic battering, and b) safely above and thus out of range of tacit civilizational threats, such attacks involving torpedoes or commandeered aircraft. The tethered ring is an optimal "stepping stone" infrastructure for furnishing humanity with a safe, affordable, and sustainable means to escape Earth's gravity, expand its civilization into space, and ultimately evolve into a multi-planetary species.

Brief explanation and full whitepaper: https://www.project-atlantis.com — video explanation: https://youtu.be/k5fki-C3r70

This repository is an interactive Three.js model of the ring, its transit system and elevators, and a mass-driver space launcher, with in-browser video recording of repeatable camera shots.

## Requirements

- **Node.js 20 or newer** (Node 25 tested) with npm. Download from https://nodejs.org/.
- **Git LFS**, for the planet terrain tiles in `assets/` (about 5 GB).
- A browser with WebGL 2. Video recording additionally needs WebCodecs: current Chrome, Edge, Firefox (130+) or Safari (17+). Chrome/Edge can stream large recordings straight to disk.

Install Git LFS:

| Platform | Command |
|---|---|
| Windows (PowerShell) | `winget install GitHub.GitLFS` (or the installer from https://git-lfs.com) |
| macOS | `brew install git-lfs` |
| Fedora | `sudo dnf install git-lfs` |
| Debian / Ubuntu | `sudo apt install git-lfs` |

## Setup

The commands are the same in PowerShell (Windows) and in a POSIX shell (Linux/macOS):

```
git clone https://gitlab.bommanager.org/alastair/tethered-ring.git
cd tethered-ring
npm install
npm run setup
```

`npm run setup` runs `git lfs install --local` and `git lfs pull` (planet tiles), then downloads the remaining textures into `textures/` from project-atlantis.com. It is safe to re-run; only missing files are downloaded. To refresh just the textures use `npm run sync-textures`.

Dependencies do not need install scripts, so `.npmrc` sets `ignore-scripts=true`.

## Running

```
npm run dev
```

Open the URL Vite prints (usually http://localhost:5173/). Useful URL parameters:

| Parameter | Effect |
|---|---|
| `?preset=<id>` | Load a scene preset, e.g. `?preset=toOrbitFromMoon`. The **Scene → Preset** dropdown does the same. |
| `?enableVR=true` | Enable WebXR (shows an "Enter VR" button). |
| `?planetAssets=earth,hawaii` | Override which terrain tile sets are streamed. |
| `?quality=auto\|high\|balanced\|low` | Graphics quality (see below). Without it, the last choice is remembered. |

### Graphics quality

**Scene → Graphics quality** trades rendering resolution for speed:

- **Auto** (default) starts at full quality and lowers the render resolution in steps while frames take longer than about 24 ms, then raises it again when there is headroom. Use it on laptops and 4K screens.
- **High** renders at the screen's full resolution (up to a 2x device pixel ratio).
- **Balanced** and **Low** cap the pixel ratio at 1.5 and 1, and switch distant objects to simpler geometry sooner.

Level of detail is chosen from each object's size in real screen pixels, so a 4K or high-DPI screen automatically gets finer detail and a narrow-field close-up keeps full detail. Recordings always render at full quality, whatever this setting is, so a shot looks the same on every computer.

Open the browser developer tools (F12) for console output. `window.tetheredRing` exposes the app objects (scene, camera, launch and transit systems, parameters) for inspection.

## Controls

Mouse: drag to orbit, right-drag to pan, wheel to zoom. The **Controls** panel holds every parameter, grouped by subsystem. Press the **Keyboard shortcuts** button for the full list; the most useful keys are:

| Key | Action |
|:---:|---|
| `O` / `I` | Orbit the planet centre / the ring centre |
| `P` | Orbit the object or surface point under the mouse (moving objects are tracked) |
| `0`–`5` | Track the nearest launch vehicle, adaptive nut, launch sled, transit vehicle, elevator car, coil marker (press again to release) |
| `9` | Stationary tracking: the camera stays put and pans to follow |
| `Q` | Toggle auto-rotation |
| `Z` / `X` | Slow zoom in / out |
| `U` / `D` | Climb / descend (press repeatedly to change the rate) |
| `R` / `L` | Raise / lower the ring (or deploy/retract the evacuated tube) |
| `W` | Jump to the camera preset selected in **Camera → cameraPreset** |
| `E` / `C` | Follow the elevator cars / the transit vehicles |
| `A` / `K` / `B` | Shot: add keyframe / remove last keyframe / preview |
| `Space` | Pause or resume simulated time |
| `S` | Update the engineering specs summary (**TextOutput** folder) |

Keys are ignored while you are typing in a GUI field.

## Recording video and repeatable shots

Recording happens entirely in the browser; no tar files, PowerShell or ffmpeg are needed. Open **Shots & Recording** in the Controls panel.

1. Set the **Output video** options: resolution, frame rate, duration, preferred codec and container. AV1 is preferred; if the browser cannot encode AV1 at that size, H.264 (then HEVC, then VP9) is used automatically. The default bitrate is deliberately high (about 0.25 bits per pixel per frame for AV1, 0.45 for H.264); set **Bitrate Mbps** to override it.
2. Build a shot. Either:
   - **Keyframes:** move the camera and press `A` (or **Add camera keyframe**) at each point; let simulated time run between keyframes (`Space` pauses). The first keyframe fixes the shot's start time. `B` previews.
   - **Live take:** press **Start live take** and fly the camera (keyboard tracking modes work too). Every frame's camera pose, and any parameter you change, is recorded. With **Encode live take** on, the video is written at the same time.
3. **Render shot to video** renders the shot frame by frame at a fixed time step (independent of how fast your computer renders) and downloads the file, or streams it to the file you choose when **Stream to file** is on (recommended for long, high-resolution videos).
4. **Export shot file** saves a `.shot.json` file. **Import shot file** on any computer restores the preset, every parameter, the simulated start time (and therefore where every vehicle is on its track), the camera path and the output settings, so rendering it produces the same footage. Importing a shot made with another preset reloads the page with that preset first.

**Wait for terrain tiles** pauses each frame until the planet's terrain has finished streaming, so frames never contain half-loaded terrain.

### Converting or re-encoding (optional)

The recordings are ready to use. If you want to re-encode one with ffmpeg anyway (for example with SVT-AV1):

```
ffmpeg -i shot.mp4 -c:v libsvtav1 -crf 20 -preset 4 shot-svtav1.mkv
```

The command is identical in PowerShell and POSIX shells once ffmpeg is on your PATH.

## Development

| Command | Purpose |
|---|---|
| `npm run dev` | Development server with hot reload |
| `npm run build` | Production build into `dist/` |
| `npm run preview` | Serve the production build |
| `npm run lint` | ESLint |
| `npm test` | Unit tests (Node's built-in test runner) |
| `npm run smoke` | Loads the app in headless Chrome/Chromium and reports console errors plus a screenshot |

`npm run profile -- --preset <id>` reports per-subsystem CPU time, GPU time, draw calls, triangles and the heaviest objects in view. Add `--width 1920 --height 1080 --dpr 2` to emulate a 4K screen (the same options work for `npm run smoke`), and `--camera "<js>"` to move the camera first (`app` is in scope).

`npm run smoke` finds Chrome, Chromium or Edge automatically; set `CHROME_PATH` if it cannot. Set `SMOKE_GPU=1` to use the real GPU (the default software renderer is very slow at decoding terrain tiles). Examples:

```
# POSIX
SMOKE_GPU=1 npm run smoke -- --wait 30 --out smoke.png
# Windows PowerShell
$env:SMOKE_GPU=1; npm run smoke -- --wait 30 --out smoke.png
```

The production build does not copy the runtime data folders (`assets/`, `textures/`, `models/`, `basis/`); deploy them next to `dist/`'s contents.
